SOLIDWORKS-PDM性能测试

在 SOLIDWORKS PDM Professional 库中执行的几乎所有操作都会与 SQL Server 组件交互。因此，操作执行缓慢很可能源于 SQL Server 本身性能问题。性能问题也可能来自客户端环境、网络连接/延迟、服务器硬件资源等

PDM 常见性能问题发生场景：

  • 检入 Check In
  • 检出 Check Out
  • 获取版本 / 获取最新版
  • 显示“包含”与“使用位置”
  • 显示材料明细表 BOM
  • 工作流状态变更
  • 管理操作（如修改权限）

影响 SQL Server 性能的因素：

系统硬件、网络架构、操作系统、存储硬盘类型（SSD/机械）、数 据库应用、客户端应用。

A) 使用 Ping

Windows 自带命令行工具，用于测试网络延迟与丢包。

命令示例：ping <服务器名> -t -l 1000- -t：持续 ping；-l：指定数据包大小（建议 1000~1450 字节）

建议至少运行 3~4 分钟，延迟应稳定 <200ms，丢包率 0%。同时用 IP 地址与服务器名分别测试，排查 DNS 解析问题。

B) 使用性能监视器 PerfMon

Windows 自带系统性能监控工具，可远程监控 SQL Server / 归档服务器。可保存 BLG 日志提交给技术支持。

参考知识库：S-025698（SQL）、S-038515（归档服务器）。

C) 路由跟踪 Tracert

用于查看客户端到服务器经过的路由节点（跳数）与每跳延迟，定位网络瓶颈节点。命令：tracert <服务器地址>

请求超时通常是路由器安全策略，不代表故障。

D) 使用 SQL Profiler

i) SQL Profiler 作用：捕获 SQL Server 中执行最慢的查询语句，定位数据库层面性能瓶颈。可保存为 .trc 跟踪文件用于后续分析。
ii) 安装：随 SQL Server 安装包一起安装，选择“管理工具 - 完整”。SQL Server 2016+ 需单独安装 SSMS。

iii) 使用方法

  1. 打开 SSMS → 工具 → SQL Server Profiler
  2. 新建跟踪，连接目标服务器
  3. 使用 Standard 模板，取消安全审计与会话事件
  4. 勾选“显示所有列”，添加 DatabaseName、HostName
  5. 设置过滤器：库名、主机名、持续时间 ≥1
  6. 在复现问题前启动跟踪，复现后停止并分析最长耗时语句

E) 使用 SSMS 活动监视器

实时查看 SQL 进程、等待任务、数据库 I/O、批处理请求、阻塞、资源等待、高开销查询。

关键：Head Block 列可查看阻塞其他查询的语句。建议刷新间隔 ≥10 秒，避免影响服务器性能。

F) 使用 PDM 连接测试工具

用于测试 PDM 所有链路连通性：归档服务器、SQL Server、SNL 等。性能问题重点关注 Ping 结果。

工具与说明见知识库 S-069274。

G) 使用 PDM 状态报告工具

用于抓取 PDM 库数据库状态、配置、性能快照，生成诊断报告。支持保存为 .dat 文件，可离线查看并提交技术支持。

工具见知识库 S-066526。

检入慢-缓存影响

检入检出和变更状态在PDM运行逻辑就是将SQL表内的相关列值信息做更新，在多个表内插入或新建新版本的所有记录和列值，然后将所有新产生的新版本物理文件上传到存档服务器内的0-F目录内，并更新对应的index.xml文件。

在某些情况下，如果所处理的库包含许多本地缓存和检出的文件夹和文件，即使检入单个文档，也可能需要很长时间才会显示“检入”对话框。通常，仅当用户以特定用户身份登录到特定计算机上的库时，才会出现这些情况。

要核实的一点是：SOLIDWORKS® Professional PDM 应用程序如何在检入期间定义父工程图的处理。默认情况下，检入操作将扫描所有缓存的文件夹，以便将可能的父工程图纳入检入。检入非 SOLIDWORKS 文件时，也可能会发生该问题。根据客户端计算机上当前缓存文件夹的结构，此扫描可能会增加大量开销，导致在出现“检入”对话框之前长时间延迟。

要验证设置：

在 SOLIDWORKS PDM 管理工具中，右键单击“用户”，然后单击“设置”。在“检入”部分中，停用“在整个库中查找工程图”选项，然后重试检入。
