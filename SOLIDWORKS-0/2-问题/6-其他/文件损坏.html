SOLIDWORKS 文件损坏

在 Windows® 文件资源管理器中右键单击 SOLIDWORKS 文件时，为什么不会出现包括“打包”、“重命名”、“替换”和“移动”的 SOLIDWORKS® 菜单？。

原因

通常，SOLIDWORKS® 的外部因素可能会导致文件损坏。其中包括操作系统、网络、电子邮件、FTP、故障硬件（硬盘驱动器）等问题。但是，软件中的缺陷也可能会导致文件损坏。

电源波动（可能会影响您的计算机设备）是导致文件损坏的常见原因。不间断电源 (UPS) 可以防止文件和硬件损坏。

文件出现损坏的另一个常见原因是用户缺乏耐性。许多用户可能会结束一个似乎需要很长时间才能完成任务的应用程序。这可能会损坏会话中打开的文件。

硬件问题（如磁盘控制器故障或内存故障）也可能会导致文件损坏。通过添加 UPS、用户培训和定期系统维护及测试，可以减少文件损坏的可能性。经常用可靠的备份和恢复工具进行备份也是相当不错的保护方法。

网络故障也可能会造成文件损坏，尤其是当用户通过网络打开和保存 SOLIDWORKS 文件时。确认您正在服务器和客户端计算机上为网卡使用最新的驱动程序版本。SOLIDWORKS 使用相同的访问例程来打开、关闭和保存文件，而无论是从网络还是本地硬盘驱动器打开文件。操作系统和设备驱动程序负责控制网络行为。SOLIDWORKS 技术支持只能提供有限的网络建议，因为建立和运行网络的过程中存在诸多变数。建议向网络专家咨询。当用户遇到网络问题时，请扫描服务器和客户端计算机的硬盘驱动器，以了解是否有错误和驱动程序更新。

如果遇到软件缺陷，请在另一个文件中记录重现损坏的精确步骤。这有助于为软件中的实施开发预防性修复程序。

决策树流程

结构化中文版（按分支阅读）

🔰 起点：在 SOLIDWORKS 中无法打开文件

分支一：检查文件大小

文件大于 40 KB？

  • ✅ 是 → 继续下一步
  • ❌ 否 → Case closed。无需向 SOLIDWORKS 技术支持提交服务请求(SR)。

分支二：检查参考文件

参考文件能否打开？

  • ✅ 是 → 判断文件类型（零件/装配体 或 图纸）
  • ❌ 否 → 检查是否能在 Quick View（快速查看） 或 eDrawings 中打开
    • ✅ 能打开 → 用户是否知道复现损坏的步骤？
      • ✅ 知道 → 如果你也能复现步骤 → 向 SOLIDWORKS 技术支持提交**关键级(Critical)服务请求(SR)**，以便修复工作流
      • ❌ 不知道 → 文件是否能在 DocEdit 中打开？（参见 QA00000112637）
        • 2014 及更早版本 → 用户是否知道复现损坏的步骤？
          • ✅ 知道 → 提交关键级(Critical)服务请求(SR)。预期说明：
            1. 研发部门可能无法修复该文件。
            2. 研发部门至少需要 3 个工作日进行审查。
            3. 研发部门无法回答损坏原因。
            4. 研发部门无法回答如何避免再次发生。
          • ❌ 不知道 → Case closed。无需提交 SR。
    • ❌ 不能打开 → 用户是否有备份？
      • ✅ 有备份 → 无法修复。必须找到备份或重新创建文件
      • ❌ 无备份 → 用户能否以图形显示为参考重新创建文件？
        • ✅ 可以 → 保存修复后的文件，并确认能重新打开该文件
        • ❌ 不可以 → 无法修复。必须找到备份或重新创建文件

分支三：判断文件类型（参考文件可打开时）

零件 or 装配体 还是 图纸？

  • 📄 图纸 → 图纸损坏

    • 用户是否有备份？
      • ✅ 有备份 → 无法修复，必须找到备份或重新创建文件
      • ❌ 无备份 → 无法修复，必须找到备份或重新创建文件

  • 🔧 零件 →

    • SOLIDWORKS 能否修复该文件？
      • ✅ 能修复 →
        • 是，特征历史已恢复（2017 以上版本可用）
        • 是，特征历史未恢复（2018 以上版本可用）
        • ⬇ 用户是否有备份？
          • ✅ 有备份 → 无法修复，必须找到备份或重新创建文件
          • ❌ 无备份 → 无法修复，必须找到备份或重新创建文件
      • ❌ 不能修复 → 用户是否知道复现损坏的步骤？
        • ✅ 知道 → 提交关键级(Critical)服务请求(SR)。预期说明：
          1. 研发部门可能无法修复该文件。
          2. 研发部门至少需要 3 个工作日进行审查。
          3. 研发部门无法回答损坏原因。
          4. 研发部门无法回答如何避免再次发生。
        • ❌ 不知道 → Case closed。无需提交 SR。

  • 🔩 装配体 →

    • 系统性地解除压缩(Unsuppress)零部件，以找出损坏源
      • 子装配体是损坏源
      • 零件是损坏源
    • 用户是否知道复现损坏的步骤？
      • ✅ 知道 → 提交关键级(Critical)服务请求(SR)。预期说明：
        1. 研发部门可能无法修复该文件。
        2. 研发部门至少需要 3 个工作日进行审查。
        3. 研发部门无法回答损坏原因。
        4. 研发部门无法回答如何避免再次发生。
      • ❌ 不知道 → Case closed。无需提交 SR。
